## 二、發現並修正的問題

### 這一輪（2026-10-24～25，收尾檢查）

**版面**
1. **寬螢幕的日記被擠到右頁下方**：整頁面板的 class 和筆記本的 `.page` 撞名。改名後，日記從右頁最上面開始。
2. **固定在底部的按鈕蓋住內容**：日記的心情格子、情緒詞、輸入框會被「下一步」「寫好了」擋住。改成按鈕接在內容後面。
3. **卡片在自己裡面捲動，按鈕被切掉一半**（志豪的內心話，iPad 橫拿）：改成整個面板一起捲。
4. **手機橫拿時畫面只剩中間一小條，字縮到 7–10px**：橫拿也攤開成左右兩頁、用滿寬度。
5. **大螢幕上字和按鈕大得誇張**：所有尺寸改用有上限的單位（`--u: min(1cqw, 5px)`）。
6. **手機群組畫面的字只有 7–10px**：手機放大、字至少 11px，已讀人數移到照片下面。
7. **認不出誰是誰**（把閃電號碼布的小雨看成老師）：每個人腳下加名字。

**劇情與畫面一致性**（新的畫面一致性測試抓到）
8. **十處有人說話，畫面上卻沒有他**（林老師、志豪、佳佳、冠宇），或場景裡沒有主角。改成說話的人會走進畫面。
9. **小雨和阿明「成為朋友」的選擇在結局沒有下文**（其他四個角色都有）：各補一句呼應週五的話。

**英文版**
10. **同一個詞有兩種翻譯**：作業本（homework／workbook）、器材室（equipment room／storeroom）、「她哪有錢買禮物」少了 even。統一。

**效能與記憶體**
11. **背景圖的快取不會清掉**：一張約 5 MB，玩一輪累積 20 多張。舊平板的 Safari 可能因為記憶體不夠重新載入頁面。改成只留最近 9 張，舊的釋放掉。
12. **分頁沒有小圖示**（每次載入都有一個 404）：加上金色閃電。

### 測試工具本身的誤報（記錄下來，避免以後誤判）

- 「對話框是空的」：打字效果剛開始時本來就沒有字；亂玩測試每一步讀整頁文字，會稍微拖慢計時器。改成空白超過 0.4 秒才算，之後 0 次。
- 「日記的 HTML 變成真的標籤」：一週回顧那行有兩個相鄰的粗體數字。改成直接找日記裡打的 `<b>bold</b>` 有沒有變粗體。
- 「英文版的 html lang 還是中文」：測試在按語言按鈕之前就讀了。按下去之後是 `en`，正常。

## 四、評估：目前的狀態

**可以做到的**
- 六個角色都能完整玩完，中英文的機制完全一樣，英文的人名、數字、用詞一致。
- 從手機橫拿到 2K 螢幕都排得下，字不會太小也不會太大。
- 亂按、暫停、重來、日記亂打都不會壞，日記裡打的 HTML 不會被執行。
- 設計原則和多視角交織的規則都有自動化測試把關，以後改劇本會自動檢查。

**這份測試不能回答的**
- **只在 Edge（Chromium 核心）測過**，沒有在 iPhone／iPad 的 Safari 上自動測。大部分排版兩者一樣，但 Safari 偶爾有自己的差異，請用真的 iPad 再玩一次。
- 台詞是否像台灣國小高年級學生說的話，需要真人試玩或老師審閱。
- 新角色（性別氣質、自閉症類群）的描寫是否得當，需要特教、性平、輔導專業人員審閱。
- 遊戲對學生的情意影響，需要依 `docs/研究施測安全流程.md` 做正式研究。

**還沒做的**
- 教案、學習單（協作 AI 報告有內容，還沒整理成文件）。
- 「玩完一個角色後，選角畫面標示你見過誰」（構想）。
- 報告列的部分參考來源需要逐筆查證，才能寫進論文。
